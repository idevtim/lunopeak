# LunoPeak v1.3.1

A bigger-than-it-sounds patch. Headline fix is Linux: LunoPeak now renders correctly on NVIDIA proprietary + wlroots-based Wayland compositors (Hyprland, Sway, river), where v1.3.0 could launch with an entirely transparent content area. Riding alongside that fix: a rearrangeable dashboard, GitHub PRs in Work Graph, per-file dirty-state on Repos, and accurate month-to-date spend.

## What's new

### Rearrangeable dashboard
- **Drag cards to swap them.** Enter edit mode on the Dashboard and drag any card onto another to swap their positions — works for both the hero pair and the responsive operational grid. Layout is pointer-event-based (so it cooperates with touchpads, trackpoints, and pen input), and your order persists in `localStorage` per grid instance.
- **Reset to default.** A reset action discards the saved order and restores the original layout without losing any data.

### GitHub pull requests in Work Graph
- **Open PRs surface in the sidebar.** The "Pull Requests" card on the Work Graph view now lists your open PRs (across the repos LunoPeak knows about), pulled via the local `gh` CLI and cached so re-opening the view is instant.
- **Auth state is honored.** If `gh` isn't installed or you're logged out, the card explains exactly which step is missing — install vs. `gh auth login` — instead of just looking empty.
- **Out-of-band loading.** PR fetches don't gate the rest of the Work Graph skeleton: cheap queries paint immediately, then the PR list drops in once `gh` returns.

### Repos: per-file dirty state and filter pills
- **Click any repo row to expand it.** Expanded rows show every uncommitted file with its staged / unstaged status code (the `git status --porcelain` row, with renames flattened to the new path). Untracked files show as `??`.
- **Filter chips on the four StatCards.** The Active / Dirty / Unpushed / Total tiles are now clickable filters — tap one to scope the list, tap again to clear. Empty buckets are disabled so you can't filter into a zero-result page.
- **"Mine" activity is tracked separately.** Repo activity now distinguishes commits authored by your local git user from team activity, so views can show "what I did" vs. "what happened in the repo."

### Month-to-date spending — for real this time
- **"Spend this month" is now month-to-date.** The dashboard StatCard previously reflected the full rolling cost-history total; it now sums only days within your current local calendar month, so a fresh month doesn't inherit last month's number on day 1.
- **Budget alerts agree.** Monthly budget alerts use the same MTD math, so threshold notifications fire off the right number and reset cleanly at the month boundary.

## Fixes

### Linux: WebView renders on NVIDIA + wlroots Wayland
- The `.deb` and `.rpm` bundles now ship a custom `.desktop` entry that prefixes the Exec line with `WEBKIT_DISABLE_DMABUF_RENDERER=1`. WebKitGTK's dmabuf compositing path silently fails to paint the WebView under NVIDIA's proprietary driver on wlroots compositors, leaving the title bar visible but the rest of the window transparent. The env var forces the fallback compositing path, which works reliably.
- This is a no-op on X11 and on Wayland compositors where dmabuf works correctly (e.g. GNOME/Mutter), so there's no impact on healthy setups. The AppImage embeds the same desktop entry, so the fix applies to all three Linux bundle formats.

### Skeletons match their real views
- Every async view's skeleton (Dashboard, Costs, Live, Repos, Sessions) was re-shaped to match the actual content it stands in for, eliminating the layout-shift flash on first paint.

## Tentative fix — needs your real-world testing

- **AppImage on NVIDIA proprietary.** v1.3.0 aborted at startup with `Could not create GBM EGL display: EGL_SUCCESS. Aborting...`, caused by the bundled `libwayland-egl.so.1` (and its mesa siblings) colliding with the host's NVIDIA driver. v1.3.1's AppImage now strips those libs at build time so the launcher falls through to the host's NVIDIA-compatible copies — the same behaviour the `.deb` and `.rpm` already had. This is the path other Wayland apps converged on for the same crash, but real NVIDIA proprietary setups vary enough that we'd like confirmation from users in the wild before declaring it solved. If the AppImage still fails to launch on your machine, please file an issue with your distro, compositor, and NVIDIA driver version. Until we've heard from a few of you, the `.deb` / `.rpm` remain the safest choice on NVIDIA.
