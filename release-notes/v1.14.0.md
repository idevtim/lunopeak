# LunoPeak v1.14.0

Your plan limits tell you how much of the week you've used. This release adds the other number you've been checking by hand: how full each running conversation's context window is. Every Claude, Codex and Cursor session you have open now shows its context fill in the Live view, the menu bar and on the dashboard. You can also put it in your terminals themselves.

## What's new

- **Each running session shows how full its context is.** For Claude Code, LunoPeak finds each running `claude` process by its PID, finds the conversation it belongs to, and reads how big the most recent prompt was. That's the same figure Claude Code uses when it warns you it's about to compact. You see it as a percentage of the model's window. So you'll see, for example, "14% · 141K / 1M" for a session that's still fresh, and you'll know which of your five terminals is about to compact before it happens. Codex sessions get the same treatment, read from the token counts Codex records after every turn, against the window size Codex reports for the model. Cursor only saves a percentage for each chat, so Cursor rows show the percentage without token counts.

- **The menu bar panel has a "Running now" list.** Under the provider bars, a compact row for each live session shows its name, folder, a thin bar and its context percentage. A pulsing dot marks the Claude sessions that are working right now. Open a provider tab and the list narrows to just that provider's sessions, below its 5-hour, weekly and Fable bars. These are deliberately smaller than the plan bars: those are limits on your whole account, and these are one conversation each. The panel is a little taller to make room, and the list scrolls if you have more sessions running than fit.

- **The Live view shows context for every process.** Each process card now has a Context row with a bar, a percentage, tokens used out of the window, and the model. A new Peak context card at the top shows the fullest session you have running. The bar turns amber at 70% and red at 85%. Claude processes are also matched to their own conversation exactly now. Before, when two Claude sessions ran in the same folder, LunoPeak guessed which one was which from the folder alone. Sometimes a card showed the other session's last action.

- **The dashboard has a "Running now · context" section,** just below Rate limits. It lists each live session's context fill, model and token count, and shows how many sessions are running and how many are busy right now. Like the other dashboard cards, you can drag it somewhere else with Edit layout.

- **Context and limits in your Claude Code terminal.** Turn it on in Settings → Terminal and every Claude Code session gets a line under the prompt: a bar for this session's context fill, your 5-hour and weekly limits, your Fable weekly limit, and what the session and your day have cost so far. When a limit passes 70% it shows when it resets. By default numbers turn yellow at 70% and red at 85%. It updates on every message and never goes to the network, so it doesn't slow Claude Code down. If you already use a status line — ccstatusline, ccusage, your own script — LunoPeak keeps it and adds its line underneath. Turn the toggle off and your old status line is put back.

- **You choose what the terminal line shows.** Settings → Terminal → Customize the line lists every piece: context, 5-hour, weekly, model limits like Fable, session cost, today's cost, and — off to start with — the model, the folder and the git branch. Switch each one on or off and move it up or down. You can also turn off the context bar or the token count, turn off colors, say when a limit shows its reset time (near the limit, always, or never), pick the separator, and set the percentages where numbers turn yellow and red. A preview above the list shows the exact line as you go, and open Claude Code sessions pick up changes on their next update without a restart.

- **The context % gets exact once the status line is on.** Claude Code tells the status line the real size of each session's context window. LunoPeak keeps that and uses it in the Live view, the menu bar and the dashboard, instead of working the window out from the model name.

- **Codex terminals too, as far as Codex allows.** Codex can't run another program in its status line yet, so LunoPeak can't add its own line there. What it can do is switch on Codex's built-in items: model, context used, 5-hour and weekly limits, and git branch. Same toggle page. If you'd already picked your own items, turning this off puts them back.

- **The menu bar stops showing out-of-date usage after an update.** The menu bar helper can keep running for weeks after the app itself updates. It could keep showing usage it saved before the update, which was missing the Fable weekly bar. Now it notices that saved usage came from an older version and fetches fresh numbers from Anthropic.

## One thing worth knowing

Claude's transcripts don't record the size of the context window. With the Claude Code status line on, LunoPeak gets the real size from Claude Code. Without it, LunoPeak works it out from the model. Fable, Mythos, Opus 5 and 5.5, Sonnet 5 and Opus 4.6–4.8 count as 1M. Older models count as 200K. Any session that has already gone past 200K is counted as 1M, whatever the model. If you run one of the 1M models on a 200K window, its percentage will read lower than it really is. The token count next to it is always exact.

Codex doesn't record which process is working on which conversation, so LunoPeak pairs each running Codex process with the newest conversation in its folder. With two Codex sessions in one folder, which percentage goes with which process is a best guess. Codex conversations with activity in the last 10 minutes always appear, even when no process could be matched to them.

Cursor chats count as running if you've used them in the last 30 minutes while Cursor is open.

Grok isn't tracked. There's no Grok coding tool on your machine whose conversations LunoPeak can read. Same reason Grok spend isn't in Costs.

The terminal status line points at wherever LunoPeak is installed. Move the app and Settings → Terminal offers a Repair button. If you're running LunoPeak straight from the disk image, move it into Applications first. Claude Code only runs status lines in folders you've trusted, the same rule it uses for hooks. The "today" cost comes from LunoPeak itself, so it only shows while the app or its menu bar icon is running. The session cost always shows.

Short-lived Claude sessions that hooks and plugins start in your temp folder are left out, since you didn't start them.

## Works on

- **macOS** 10.15+ (Apple Silicon and Intel)
- **Windows** 10+ (x64 and ARM64)
- **Linux** (x86_64)
