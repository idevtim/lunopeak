# LunoPeak v1.3.0

Cursor joins Claude Code and Codex as a first-class agent. The Live view, Setup card, and Settings toggle all light up for it. Codex now stays on by default for everyone — no more carrying a stale "off" from older builds. Plus a clutch of installer and auth-resilience fixes you'll feel without noticing.

## What's new

### Cursor support
- **Cursor in Settings → Agents.** New toggle next to Claude Code and Codex, on by default. Disable it to drop Cursor's data out of every aggregation, scan, and live view in one click.
- **Cursor in the Live view.** Composers updated within the recent activity window appear with their workspace cwd, the last bubble's preview text, and the actual Cursor app icon. Active Cursor processes get bucketed against their session, same as Claude/Codex.
- **Cursor in Setup.** New card surfaces the install path, project count, and rule count. Cursor's MCP servers (from `~/.cursor/mcp.json` and per-project metadata) merge into the existing MCP list with a `cursor` scope tag.
- **The real Cursor app icon.** Pulled from `Cursor.app` on first build and used everywhere the brand mark appears — full color, properly sized, not a generic placeholder.

### Codex stays on, for real this time
- **One-shot migration.** Settings files written by v1.0/v1.1 builds shipped with `codex: false` baked in, so anyone who carried that file forward saw Codex stuck off on "fresh" installs. A first-run migration force-enables every known agent once, then sets a sentinel so it never overrides a later toggle. Existing user choices are respected — this only fires when the sentinel is missing.
- **Symmetric fallbacks.** The `codex_enabled` helper used to default to `false` on a settings-load error, asymmetric with `claude_enabled`. Both (and the new `cursor_enabled`) now default to `true` so a transient config-read error never silently hides agent data.

### Auth resilience
- **Claude credentials auto-refresh.** OAuth access tokens are now refreshed transparently when expired and persisted across launches, so connected accounts stop dropping out after long idle periods.

### Windows installer
- **`currentUser` install hooks.** NSIS now runs in per-user install mode by default — installs without elevation prompts and leaves no orphan entries under `Program Files` when you uninstall.

### Quality-of-life
- **Release skill bundles.** `/release-mac`, `/release-win`, `/release-linux`, and `/release` skills automate the full local build → sign → publish workflow per platform. Pair them with the existing `RELEASE.md` runbook.
- **`gh auth` check robustness.** Build scripts now use try/catch on the GitHub CLI auth probe, so a chatty stderr from `gh` doesn't fail the script's gate.
- **macOS Reopen handling.** Re-launching while LunoPeak is already running (Dock click, Launchpad, Finder) reliably brings the main window back into view from Accessory mode.

## Platform support

- **macOS** 10.15+ (Apple Silicon and Intel)
- **Windows** 10+ (x64 and ARM64)
- **Linux** (x86_64) — deb, rpm, and AppImage

## Notes for existing installs

- The agent migration runs once on first launch under v1.3.0. If you'd intentionally turned Codex off on v1.2.x and want it to stay off, just toggle it back off after upgrade — your second-and-after choices are sticky.
- Cursor live activity reads Cursor's chat database in read-only mode (`mode=ro&immutable=1`), so it won't fight Cursor for the lock when Cursor is running. Cursor doesn't expose a structured per-tool log, so its events show as `Chat`/`User` rather than per-tool calls.
